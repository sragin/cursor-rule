# handoff — 인계 작성

세션 종료 시 실행한다. 아래 순서를 그대로 따른다.

## 1. 사실 수집

기억이 아니라 명령으로 확인한다. 다음을 모두 실행한다.

```
git rev-parse --abbrev-ref HEAD
git log --oneline -15
git status --porcelain
git diff --stat HEAD
```

머신 이름은 PowerShell 에서 `$env:COMPUTERNAME` 으로 확인한다.

## 2. 기록 원칙

- **확인된 사실만 적는다.** 추정은 "미해결 이슈"에 옮기고 가설임을 명시한다.
- 해결한 문제는 증상이 아니라 **재현 조건과 원인**을 적는다.
- **대화에서만 오간 결정은 반드시 옮긴다.** 세션 기록은 이 머신을 벗어나지 못한다.
- 실차 테스트를 했다면 **일자·장비**, **사무실과 달랐던 점**, **재현 조건**을 적는다.
  재현되지 않았으면 "재현 실패"라고 명시한다.
- 실차 로그·덤프·레코딩 원본은 커밋하지 않는다. 결론만 남긴다.
- 실제 환경 값(IP·포트·경로·시리얼명)은 `memory.md` 에 적지 않는다.

## 3. memory.md 갱신

- **"현재 상태"**: 1번에서 수집한 값으로 덮어쓴다(작업 머신 / 브랜치 / 마지막 커밋 / 작업 트리 상태 / 진행 중인 작업 / 미해결 이슈 / 다음 머신에서 할 일).
- **"이력"**: `### YYYY-MM-DD / 머신명 / 브랜치` 항목을 **추가**한다. 기존 항목은 수정하지 않는다.
  각 항목에 `한 일 / 확인한 사실 / 막힌 것`을 쓴다.
- **"다음 머신에서 할 일"**은 실행 가능한 단위로 쓴다.
  "테스트 계속" 같은 표현은 금지. "X 조건에서 Y 를 실행해 Z 로그 확인" 처럼 쓴다.

## 4. CLAUDE.md 이관 제안

같은 지적이 **2회 이상** 나왔거나 다음 세션에도 계속 적용될 규칙이면 `CLAUDE.md` 로 옮길 것을 **제안만** 한다. 직접 수정하지 않는다.

## 5. 커밋

```
git add memory.md
git commit -m "chore: 인계 기록 갱신"
```

- `memory.md` 외의 파일을 함께 스테이징하지 않는다.
- **푸시하지 않는다.** 대신 아래 한 줄을 안내한다.

```
git push
```
